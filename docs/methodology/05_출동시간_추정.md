# 05. 출동시간 추정 (유효거리 → 시간)

[02. 도로기반 지연 추정](02_도로기반_지연추정.md)의 경사비용은 **유효거리(m)** 이고, 계수 β=6은 가정값이다. 본 문서는 이를 **시간(분)** 으로 확장하고, 계수를 **네비게이션 실주행 데이터로 실측**하며, 출동 전 과정을 **3구간**으로 분리한 과정을 정리한다.

> 입력: [01. 데이터 전처리](01_데이터_전처리.md)의 완전연결 그래프(4,756/12,886) + 안전센터 7곳 + 병원 3곳 + 집계구 78개
> 근거: 2026-08-10 회의 「주제1 - 2번 출동시간」
> 검증: NAVER Cloud Directions 5, OD 1,326쌍 수집(성공 1,325)

---

## 1. 문제 제기

02의 마지막 한계는 다음과 같았다.

> **남은 한계:** 아직 거리형 비용(속도·신호·도로폭 미반영, 절대 "분"은 아님). 향후 도로등급별 속도모델로 시간(min) 산출 가능.

여기에 회의에서 두 가지가 더 지적되었다.

1. **β=6에 근거가 없다.** 민감도 4/6/8로 방어했으나 값 자체가 실측이 아니다.
2. **소방 → 발생 → 병원 전 과정**이 필요하다. 02는 안전센터 → 현장 한 구간만 다룬다.

## 2. 3구간 분리

| 구간 | 내용 | 이동 수단 |
| --- | --- | --- |
| t1 출동 | 안전센터 → 하차지점 | 차량 |
| **t2 접근** | **하차지점 → 집계구 중심** | **도보·들것** |
| t3 이송 | 하차지점 → 병원 | 차량 |

**t2를 새로 넣은 이유.** 구급차가 집 앞까지 들어가지 못하는 것이 산복도로의 본질적 지연인데, 기존 파이프라인에는 이 구간이 없다. `amb_passable`이 12,886개 엣지 **전부 True**이고 `width_est` 최소가 4.0m(3m 미만 0개)라 폭으로 골목을 거를 수 없으며, 노트북 10의 라우팅도 `weight="length"`만 쓴다. 즉 **차량이 어디든 닿는 것으로 계산**된다.

폭 데이터를 새로 확보하는 대신, **하차지점과 집계구 중심의 실제 이격**을 들것 도보구간으로 계상해 우회했다.

## 3. 시간 비용 모델

```
t_flat(u→v)  = length / (v_base(hw_type) × V_CALIB)
t_slope(u→v) = t_flat + b_up · Δz⁺
최종 가중치   = t × k_emergency
지연          = t_slope 기준 시간 − t_flat 기준 시간
```

- `v_base`: 도로등급별 기준속도. `maxspeed` 태그가 12,886개 중 **70개(0.5%)** 에만 있어 등급 기반으로 직접 정의했다.
  `motorway 80 · trunk 60 · primary 50 · secondary 40 · tertiary 35 · residential 25 · living_street 15` (km/h), `*_link`는 −10.
- **`V_CALIB = 0.34`**: 속도 보정계수. 5-2절 참조.
- **`b_up = 0.489 s/m`**: 오르막 계수. 4절에서 실측.
- `k_emergency = 0.70`: 사이렌 주행의 신호대기·교차로 지연 감소. 축5에 시각 필드가 없어 실측 불가 → 문헌 범위 중앙값.

**t2 — 들것 도보.** Tobler 보행함수에 하중 계수를 곱한다. 차량용이 아니므로 t2에만 적용한다.

```
v_walk(s) = 6 · exp(−3.5 · |s + 0.05|) / 3.6 × 0.60   (m/s)
t2 = 왕복거리 / v_walk    (올라갈 때 장비 지참, 내려올 때 환자 이송을 각각 계산)
```

현장처치 고정시간(240초)과 출동준비 turnout(90초)은 경사와 무관한 상수라 **총시간에만 더하고 지연에서는 상쇄**된다.

## 4. 경사계수 실측

### 4-1. OD 설계

| leg | 구간 | 쌍 수 | 표고차 중앙 |
| --- | --- | --- | --- |
| A_out | 안전센터 → 집계구 | 546 | +14.8m |
| A_back | 집계구 → 안전센터 | 546 | −14.8m |
| B | 집계구 → 병원 | 234 | +39.1m |

총 1,326쌍, 성공 1,325(실패 1은 네트워크 타임아웃).

> **호출 방식 주의.** Directions 5는 `goal`에 콜론으로 목적지를 여러 개 넣어도 **경로는 1건만 반환한다.** 목적지 10개씩 묶어 212회로 수집하면 목적지별 결과를 얻지 못한다. 1건씩 1,326회 호출해야 한다.

### 4-2. 경로 표고

필요한 값은 출발–도착 직선 표고차가 아니라 **실제 주행 경로의 누적 오르막**이다. 응답의 `path`(경로 좌표열)에 그래프 노드 표고 4,756점을 보간해 부여한다. 별도 DEM을 받지 않는 이유는 OpenTopoData 공개 API가 일 1,000요청 제한이라 부족하고, 노드가 곧 도로 교차점이라 도로 위 표고를 뽑기에 적합하기 때문이다.

### 4-3. 시도 ① 절대 오르막 회귀 — 실패

```
dur_s ~ dist_m + up_m + down_m
  → up_m 계수 −0.305 (p<0.001),  down_m −0.807
```

**오르막이 클수록 빨라진다**는 결과가 나왔다. 물리적으로 불가능하다.

원인은 교란이다. 대상지에서 **긴 경로는 간선도로**라 빠른데, 절대 오르막(m)도 거리에 비례해 함께 커진다. 그래서 `up_m`이 "간선도로 여부"의 대리변수가 되어 부호가 뒤집혔다.

### 4-4. 시도 ② 왕복 짝 분석 — 실패

같은 구간을 뒤집으면 오르막↔내리막이 바뀌므로 `Δt = (b_up − b_down)·Δh` 로 경사만 분리된다는 설계였다.

```
545쌍 짝지음 → Δh 계수 0.066 (p = 0.687, 유의하지 않음)
```

**전제가 성립하지 않았다.** 왕복 경로의 길이 차이가 **중앙 517m**로, 같은 길로 돌아오지 않는다. 대상지에 일방통행이 1,794개 엣지나 있어 복귀 경로가 크게 우회하기 때문이다. *(이 자체가 산복도로 접근성의 특성이다)*

### 4-5. 시도 ③ 평균경사 회귀 — 채택

거리로 나눠 **평균 경사**로 바꾸고, `log(거리)`를 도로등급 대리변수로 통제한다.

```
소요초/거리 = c₀ + b_up·(오르막/거리) + b_down·(내리막/거리) + c₁·log(거리)
```

양변에 거리를 곱하면 `소요초 = c₀·d + b_up·오르막 + …` 이므로 **(오르막/거리)의 계수가 곧 b_up [s/m]** 이다.

대상은 대상지 내 A_out·A_back(n=1,091). 이송(B)은 간선 장거리라 주행 체계가 달라 제외했다.

| 항목 | 계수 | p | 95% CI |
| --- | --- | --- | --- |
| **(오르막/거리)** | **0.489 s/m** | **6.5e-06** | **[0.277, 0.701]** |
| (내리막/거리) | −0.043 s/m | 0.67 | 유의하지 않음 → **0 처리** |
| log(거리) | −0.0438 | <0.001 | 도로등급 대리 |

R² = 0.402, n = 1,091

> **b_up = 0.489 s/m — 100m 오르면 약 49초가 더 걸린다.**
> 내리막은 유의하지 않다. 감속 효과가 있더라도 네비 소요시간에서는 분리되지 않는다.

### 4-6. 왜 119 출동기록이 아닌가

부산 119 소방출동정보 API(`getTodayInfo`)의 출력 항목은 `regtime`·`dsraddr`·`dsrkndcd`·`dsrclscd`·`dsrsizecd`·`juriswardid1`·`juriswardid2` 뿐이다. **출동시각·현장도착시각·좌표가 없어** 소요시간 검증에 쓸 수 없다. [`검증_119출동.py`](../../code/scripts/검증_119출동.py)가 이 API를 **수요(출동 건수) 검증**에 쓰는 것이 정확한 용법이며, 도달시간 검증 경로는 네비게이션 API가 유일하다.

## 5. 절대 시간 검증 및 속도 보정

경사계수와 별개로, **모델이 내놓는 절대 소요시간이 맞는지**를 네비 실측과 대조했다. 회의록의 *"실제로 도달하는데 얼마나 걸리는지를 검정"* 에 해당한다.

### 5-1. 보정 전 — 모델이 3.5배 빨랐다

집계구 78개 각각에 대해 안전센터 7곳 중 **최단 네비 소요시간**과 모델의 t1(turnout 제외, 긴급보정 되돌림)을 비교했다.

| | 중앙값 |
| --- | --- |
| 모델 (보정 전) | 1.05분 |
| **네비 실측** | **3.67분** |
| 비율 | 0.31 |

원인은 `V_BASE`가 도로등급별 **설계속도**라는 점이다. 실제 산복도로 주행속도는 네비 실측 기준 거리 500m에서 14.0km/h, 1km에서 15.8km/h, 3km에서 20.1km/h로, 신호대기·교차로·정지발진·좁은 도로가 설계속도에 반영되어 있지 않다.

### 5-2. 속도 보정계수 도입

```
V_CALIB = 0.34      실효속도 = V_BASE × 0.34   (residential 25 → 8.5 km/h)
```

이 계수를 곱하면 모델의 평지 주행시간이 **일반 승용차(네비) 수준**과 일치하고, 여기에 `k_emergency`를 곱해 긴급주행을 반영하는 구조가 된다.

| | 중앙값 |
| --- | --- |
| 모델 (보정 후) | **3.61분** |
| 네비 실측 | 3.67분 |
| **비율** | **0.98** |
| 상관계수 | 0.782 |

### 5-3. 참고 — 경로 길이 비교

우리 그래프의 최단 도로거리와 네비의 최단 경로거리를 비교하면 중앙 **1.17배**(네비가 더 김)다. 동별로는 좌천동 1.52배로 가장 크다. OSM 차량망이 실제 내비게이션이 회피하는 좁은 길을 포함하기 때문으로 보이며, 도로폭 실측이 확보되면 줄어들 여지가 있다.

## 6. 견인력–저항 평형 모델 (물리 검증)

회의에서 요구된 crawl speed 모델을 적용했다. 구동력과 주행저항이 같아지는 평형속도를 푼다.

```
0.5·ρ·CdA·v³ + m·g·(sinθ + C_rr·cosθ)·v − P·η = 0
```

구급차 제원은 특수구급차(쏠라티급) 기준 4,500kg / 125kW / η=0.85 / C_rr=0.012 / CdA=1.8.

### 6-1. 결과 — 출력은 제약이 아니다

| 경사 | 평형속도 | residential 기준속도 | 제약 주체 |
| --- | --- | --- | --- |
| 15% | 52.4 km/h | 25 km/h | 기하구조 |
| 25% | 33.8 km/h | 25 km/h | 기하구조 |
| 30% | 28.8 km/h | 25 km/h | 기하구조 |

구급차는 **36 kg/kW**로 AASHTO 화물차 기준(약 120 kg/kW)의 1/3이라 동력에 여유가 있다. 모든 경사에서 평형속도가 도로등급 기준속도를 상회한다.

→ **산복도로 지연의 원인은 동력 부족이 아니라 기하구조(도로폭·곡률)·노면 견인한계·들것 도보구간이다.** 원인을 하나 배제한 것이므로 논거가 강화된다. 4-5절의 실측 계수(0.489 s/m)도 이 배제 논증과 정합한다 — 경사가 시간에 영향을 주긴 하지만 그 크기가 엔진 출력 한계에서 오는 것은 아니다.

### 6-2. 노면별 견인한계

등판 가능 조건은 `tan θ ≤ μ × 구동륜 하중비`(후륜구동, 하중비 0.5).

| 노면 | μ | 등판 한계 경사 |
| --- | --- | --- |
| 마른 아스팔트 | 0.80 | 40.0% |
| 젖은 노면 | 0.50 | 25.0% |
| **결빙** | 0.15 | **7.5%** |

결빙 시 7.5% 초과 구간은 진입 자체가 불가능하다. 대상지 엣지의 9.0%가 |경사| 15% 이상이므로, **겨울철 산복도로 상단 접근 불가 시나리오**로 활용할 수 있다.

### 7-3. 순위 검증 — 결론은 유지된다

- 집계구 단위 순위 상관 **Spearman 0.964**
- **다섯 개 동 전부 순위 변동 없음** (거리기준 = 시간기준)
- **민감도 9개 조합**(b_up 95%CI 3수준 × 클립 3수준) **전부 초량6동 1위**

거리 기준을 시간 기준으로 바꿔도 결론이 바뀌지 않는다. 축1 위험도와 [03. AED 후보군 추정](03_AED_후보군_추정.md)의 MCLP 결과(초량6동 7개 배치)는 **그대로 유효**하며, 02의 "결과가 β에 민감하지 않음"을 실측 계수 기준에서 재확인한 셈이다.

### 7-4. 지연의 출처

| 구간 | 지연 기여 |
| --- | --- |
| t1 출동 | 18.4% |
| **t2 들것 도보** | **35.1%** |
| t3 이송 | 46.6% |

**정책 함의가 갈린다.**

- **t1+t2 지연(53.5%)** → **AED 선배치로 대응 가능** ← 본 프로젝트 대상
- t3 지연(46.6%) → 이송 병원 표고가 인제대부산백 106m·동아대 75m로 집계구 평균(약 40m)보다 높아 발생. 병원 접근성 문제이므로 AED로 해결 불가. 보고서에서 **AED의 역할과 한계를 규정**하는 근거로 쓴다.

「이송은 내리막이라 빠르다」는 가정은 성립하지 않는다.

| ② | 경사 이상치 — 최대 60.1% | ±25% 클립 |
| ③ | 집계구 중심과 `entry_node`의 표고 불일치 최대 45.4m | 하차지점을 최근접 **선분**으로 변경 |

**② 경사 이상치의 원인.** SRTM 30m는 표고를 **정수 미터**로 반환한다. 그래서 짧은 엣지에서 1m 반올림 오차가 그대로 큰 경사가 된다.

```
길이  2.1m · 표고차 1m  → 48%
길이 11.6m · 표고차 7m  → 60%
```

실존 최급경사 도로가 약 35%이므로 물리적으로 불가능한 값이다. ±25%로 클립했으며 274개 엣지(2.1%)가 해당한다. 민감도상 클립 범위를 0.20~0.30으로 바꿔도 총시간 중앙값 변화는 0.1분 미만이라 결과는 견고하다.

**③ 하차지점 정의.** 노트북 10은 `ox.distance.nearest_nodes`로 집계구 중심을 **교차로 노드**에 스냅한다. 구급차는 도로 선분 어디에나 정차할 수 있으므로 점–선분 거리가 맞다. 노드 기준으로 재면 도보거리가 과대평가된다(노드 기준 중앙 51.5m·최대 336m).

## 9. 파라미터·한계

| 항목 | 값 | 근거 |
| --- | --- | --- |
| **b_up (오르막 계수)** | **0.489 s/m** | 네비 실측, p=6.5e-06 |
| b_down | 0.0 | 실측에서 유의하지 않음(p=0.67) |
| **V_CALIB (속도 보정)** | **0.34** | 네비 실측 대조(비율 0.98) |
| 경사 클립 | ±25% | SRTM 정수 반환 오차 제거 |
| k_emergency | 0.70 | 문헌값, 민감도 0.60/0.70/0.80 |
| 도보 하중계수 | 0.60 | 들것·환자·장비 |
| turnout / on-scene | 90 / 240초 | 지연에서 상쇄 |
| 민감도 범위 | b_up 95%CI [0.277, 0.701] | 임의 배수가 아닌 추정 불확실성 |

**남은 한계**

1. **네비는 일반 승용차 기준이다.** 구급차 긴급주행 보정 `k=0.70`은 문헌값이며 실측하지 못했다. 축5(119 출동기록)에 시각 필드가 없어 확인 경로가 없다.
2. **경사계수는 대상지 단거리 구간(A_out·A_back) 기준이다.** 이송(B) 구간을 포함하면 유의성이 사라진다(p=0.17). 간선 장거리는 주행 체계가 다르기 때문으로, 적용 범위를 대상지 내로 한정해야 한다.
3. **도로폭이 여전히 미실측이다.** t2로 우회했을 뿐 근본 해결은 아니다. 부산시 도로면 폴리곤 확보 시 t1에 직접 반영 가능하다.
4. **발생지가 집계구 중심 대체다.** 실제 심정지 좌표가 아니다.
5. **표고 30m → 2m DEM 교체 시** 경사 정밀도가 올라가고 클립 필요성이 줄어든다.
6. **왕복 짝 설계가 무산됐다.** 일방통행으로 복귀 경로가 중앙 517m 우회한다. 향후 동일 경로 강제 옵션이 있는 API를 쓰면 더 깨끗한 추정이 가능하다.
